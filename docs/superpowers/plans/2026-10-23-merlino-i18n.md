# Merlino — Lingue — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Interfaccia, menu e messaggi in inglese (predefinito) e in italiano (selezionabile), con il cambio immediato dalle Impostazioni.

**Architecture:**
- I dizionari stanno in `src/shared/i18n/` (`en.ts` fa da riferimento, `it.ts` ha lo stesso tipo), con `translate` e `translatePlural`.
- Il main tiene la lingua corrente (`src/main/i18n.ts`); il renderer la legge dalle preferenze (`src/renderer/i18n.ts`).
- Spec: `docs/superpowers/specs/2026-10-23-merlino-i18n-design.md`. Branch: `feature/i18n`, che parte da `feature/drag-and-drop`.

**Eccezione voluta alla regola "tutto il codice nel piano":** i circa 400 testi tradotti non sono qui. Scriverli due volte, nel piano e nel codice, non aggiungerebbe niente. Il piano fissa l'infrastruttura completa, le convenzioni, l'elenco dei file e il controllo finale.

## Global Constraints

- **Lingue**: `Lang = 'en' | 'it'`. La preferenza `language` è predefinita `'en'` e viene validata con `oneOf`.
- **Chiavi**: `area.significato` in camelCase. Per esempio `menu.file`, `sidebar.branches`, `working.commit`, `error.pushRejected`, `action.remote.fetch`.
  - I plurali usano `<base>.one` / `<base>.other`, con il segnaposto `{count}`.
  - I segnaposto sono `{nome}`.
- **Inglese**: frasi brevi, con lo stile delle app per macOS (sentence case, "…" per i comandi che aprono un dialog).
- **Italiano**: i testi esistenti, invariati.
- **Testi da non tradurre**: i nomi propri e tecnici (Merlino, git, HEAD, SHA, rebase, cherry-pick, stash, fetch, pull, push) restano come sono nelle due lingue, come già nell'italiano attuale.
- **Test**: la finestra resta nascosta (`MERLINO_E2E=1`); i test usano i testi inglesi.

**Files:**

- Test: `test/unit/i18n.test.ts`, `test/unit/validate.test.ts`, `test/unit/settings.test.ts`

`src/shared/i18n/index.ts`:

```ts
import { en } from './en'
import { it } from './it'

export type Lang = 'en' | 'it'
export type MessageKey = keyof typeof en
export type Messages = { [K in MessageKey]: string }
export type Params = Record<string, string | number>
/** Chiave di un plurale senza suffisso: "working.modified" per "working.modified.one" e "working.modified.other". */
export type PluralKey = { [K in MessageKey]: K extends `${infer B}.other` ? B : never }[MessageKey]

export const LANGUAGES = ['en', 'it'] as const satisfies readonly Lang[]
const dictionaries: Record<Lang, Messages> = { en, it }

/** Testo nella lingua scelta, con i segnaposto {nome} sostituiti; un segnaposto senza valore resta com'è. */
export function translate(lang: Lang, key: MessageKey, params?: Params): string {
  const text = dictionaries[lang][key]
  return params ? text.replace(/\{(\w+)\}/g, (m, name: string) => (name in params ? String(params[name]) : m)) : text
}

const pluralRules = new Map<Lang, Intl.PluralRules>()

/** Plurale: <base>.one o <base>.other secondo le regole della lingua; {count} è il numero. */
export function translatePlural(lang: Lang, base: PluralKey, count: number, params?: Params): string {
  let rules = pluralRules.get(lang)
  if (!rules) {
    rules = new Intl.PluralRules(lang)
    pluralRules.set(lang, rules)
  }
  const form = rules.select(count) === 'one' ? 'one' : 'other'
  return translate(lang, `${base}.${form}` as MessageKey, { count, ...params })
}

export const dateLocale = (lang: Lang): string => (lang === 'it' ? 'it-IT' : 'en-US')
```

- **`en.ts`**: `export const en = { 'language.en': 'English', 'language.it': 'Italiano', … } as const`, poi cresce durante i Task 2 e 3.
- **`it.ts`**: `import type { Messages } from './index'` e `export const it: Messages = { … }`.
- **`src/main/i18n.ts`**: la lingua corrente (`let current: Lang = 'en'`) con `setLanguage(lang)`, `language()`, `t(key, params?)` e `tn(base, count, params?)`.
- **`src/renderer/i18n.ts`**: `t` e `tn`, che leggono `useAppStore().preferences.language` a ogni chiamata, quindi sono reattive nei template e nei computed.
- **Preferenza**:
  - `Preferences.language: Lang`, `DEFAULT_PREFERENCES.language = 'en'`;
  - in `validate.preferences`: `language: oneOf(p.language, LANGUAGES, t('setting.language'))`.
- **Menu**: in `applyPreferences`, `setLanguage(p.language)` e poi `buildMenu((id) => send(Channels.menuAction, id))`, che la ricostruisce in ogni caso: è economico e le preferenze cambiano raramente. Da `src/main/index.ts` va tolta la chiamata a `buildMenu`.
- **`App.vue`**: `document.documentElement.lang = app.preferences.language` dentro il `watchEffect` che c'è già.
- **Impostazioni**: Generale → Aspetto, campo "Language / Lingua", un `<select>` con `data-testid="pref-language"` e i nomi delle lingue scritti nella loro lingua.

Test unit (`test/unit/i18n.test.ts`):
- segnaposto sostituiti; un segnaposto senza valore resta com'è;
- plurali in inglese (1 → `.one`, 2 → `.other`) e in italiano;
- per ogni chiave, l'italiano ha lo stesso insieme di segnaposto dell'inglese e nessun testo vuoto.
